## 一、先看这里（给老师 / 汇总同学）

### 1.1 这套东西是干什么的

参观者用手机扫大屏上的二维码，写下自己的称呼并手写签名；签名会在一两秒内飞到大屏上，化作金色沙粒落进「乐学」两个字里，同时整片字泛一次金光、签到人数 +1。提交成功后手机端会生成一张「入校通行证」，可以保存到相册。

```
参观者手机                    服务器（一个 Python 进程）              大屏（Windows 浏览器）
  ① 扫二维码 → /phone/             │                                   │
  ② 填称呼 + 手写签名              │                                   │
  ③ POST /api/signin  ───────────▶│ 存 SQLite + 签名 PNG              │
  ④ 本地生成通行证 PNG            │ WebSocket 广播 signin ───────────▶│ 名字浮现 → 金沙飘落 → 泛金光 → 人数 +1
  ⑤ 通行证二维码 /card/编号 ─────▶│ 核验页（不显示签名原图）           │
```

**不需要装 App、不需要登录、不需要连校园网**，手机走自己的移动网络，大屏用浏览器打开同一个公网地址。

### 1.4 怎么最快看到效果（不用懂代码）

**方式 A：只想看大屏长什么样（30 秒，不用装任何东西）**

双击打开 `web/screen/index.html`。这是离线演示模式，不用起服务、不用联网。

- 按 `S` 或空格 → 模拟 1 个人签到
- 按 `M` → 模拟 3 个人同时签到（可以看到错开出场的效果）
- 网址后加 `?demo=1` → 自动循环演示
- 网址后加 `?count=30` → 开场先铺好 30 人的沙粒

> 这个模式下手机端不会联动，二维码也只是示意。

**方式 B：完整走一遍「手机扫码 → 大屏出特效」（需要 3 条命令）**

见本文第四节「本地跑起来」。起服务后，电脑打开大屏页，用另一台设备（或同一台电脑开另一个窗口）打开手机页填一次，就能看到实时联动。

## 三、技术方案（给接手开发的同学）

### 3.1 技术栈与选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JavaScript，无构建、无 npm 依赖 | 双击就能打开看效果，部署时只是静态文件，现场机器再旧也少一层风险 |
| 后端 | Python 3.11+ / FastAPI 0.162 / Uvicorn 0.54 | 项目组同学更熟悉 Python；单进程就能同时托管页面、接口、实时通道，部署和 Node 方案等价，不需要额外选型 |
| 存储 | SQLite（单文件）+ 本地 `sig/*.png` | 不用装数据库、不用配连接池；签名图本来就是图片，直接落盘最省事 |
| 实时 | WebSocket（服务端原生） | 签到后 1 秒内推到大屏；连接表在进程内存里，所以**必须单 worker** |
| 图片处理 | Pillow 13 | 校验、压缩签名图 |

依赖锁定在 `server/requirements.txt`：

```
fastapi==0.162.0
uvicorn[standard]==0.54.0
pillow==13.0.0
```

### 3.2 几个关键设计

- **大屏固定舞台**：设计稿是 `1280 × 722`，整页用 `transform: scale()` 等比缩放适配任意分辨率，所有坐标、粒子落点都基于这套固定坐标系，不会出现布局漂移。
- **「乐学」是矢量不是图片**：原型图把 UI 和字样抹掉后做成 `scene.jpg` 背景，「乐学」两个字单独保存为 SVG path（`web/screen/img/lexue-paths.svg`，同时内嵌在 `index.html`）。这样特效可以用 `isPointInPath()` 精确算出字形内部的沙粒落点，金色描边和金光也能独立控制。
- **字体自托管**：标题马善政、正文思源宋体、手写名龙藏体都做了子集化，随项目一起放 `web/screen/fonts/`，断网也不掉字。
- **二维码本地生成**：`qrcode-generator 1.4.4` 放在 `web/shared/vendor/`，不依赖任何 CDN。
- **多人错峰**：每人有独立的浮现、化沙、金光时间轴，`START_GAP` 保证同时到达的人错开出场，选位置时挑离正在用的位置最远的空位，动画用自有时钟避免切后台回来瞬间跳完。

## 四、本地跑起来

### 4.1 环境要求

Python 3.11 或以上，一台能跑浏览器的电脑。不需要 Node、不需要数据库、不需要联网（依赖装好后）。

### 4.2 三步启动

```bash
cd check_in
python3 -m venv .venv
./.venv/bin/pip install -r server/requirements.txt
./.venv/bin/python server/app.py
```

看到监听 `127.0.0.1:8000` 就起来了。启动日志或 `server/data/admin_token.txt` 里是管理口令。

### 4.3 三个地址

| 地址 | 是什么 |
|---|---|
| `http://127.0.0.1:8000/screen/` | 大屏页（根路径 `/` 也会跳到这里） |
| `http://127.0.0.1:8000/phone/` | 手机端填表签名页，也可用大屏上的二维码扫开 |
| `http://127.0.0.1:8000/card/{编号}` | 身份牌二维码扫开的核验页 |

同一局域网里，把 `127.0.0.1` 换成电脑的局域网 IP，手机就能扫码真机联调（需放行 8000 端口）。

### 4.4 只想看大屏、不想起服务

直接双击 `web/screen/index.html`。页面检测到是 `file://` 会自动进入离线演示模式：不连后端、不报错，二维码用本地示意，按 `S` / `M` 就能看特效。也可以在任何地址后加 `?live=0` 强制离线。

### 4.5 常见坑

1. **手机端不能用双击 html 的方式打开**——它要往 `/api/signin` 提交数据，必须走服务地址。
2. **必须单 worker**（`--workers 1`）：WebSocket 连接表在进程内存里，开多进程会各收一份，大屏可能收不到广播。
3. **二维码地址由服务端给**：`/api/config` 默认用请求的 Host 推断。正式部署到公网时设 `CHECKIN_PUBLIC_URL`，否则手机扫出来可能指向内网地址。
4. **改了签名人数不涨是正常设计**，见 5.4。
5. **屏幕常亮在 `http://IP:端口` 下会被浏览器拒绝**，属安全策略，不是代码坏了，见 7.4。
6. **`server/data/` 里有管理口令和签到数据**，别提交、别打包、别外传。

## 五、功能说明

### 5.1 签到全流程

1. 大屏展示二维码 → 手机扫码打开填表页。
2. 填昵称（必填），展开「更多信息」可填单位 / 来访类型 / 分组 / 参观路线（都可留空）。
3. 在手写区签名（可清空重签，也可以完全不签）。
4. 提交 → 后端校验、存库、存签名图 → 通过 WebSocket 广播 `signin`。
5. 大屏收到后：名字（或签名笔迹）在天空某处浮现 → 缓慢化作金沙飘落进「乐学」→ 整片字泛一次金光 → 人数缓动 +1。
6. 手机端同时生成入校通行证，可点按钮或长按保存 PNG。

### 5.2 大屏金沙特效

`web/screen/effects.js` 对外暴露 `window.SignFx`：`arrive`（来一个人）、`prefill`（按人数预铺）、`mock` / `simulate`（彩排）、`reset`、`flash`（只泛金光）、`ready`。

| 常量 | 值 | 含义 |
|---|---|---|
| `T_HOLD` | 1800–2900 ms | 名字浮现到开始化沙的时间，每人随机 |
| `T_SPAWN` | 2000–3000 ms | 沙粒陆续散出的窗口 |
| `START_GAP` | 900–1700 ms | 相邻两人出场的最小间隔，同时到达也错开 |
| `FLIGHT_MIN/MAX` | 2600 / 3800 ms | 单颗沙粒缓慢飘落时长 |
| `FLASH_MS` | 2400 ms | 「乐学」泛金光时长 |
| `GRAINS_PER_PERSON` | 360 | 每人沙粒数 |

多人同时签到时每个人有独立时间轴和独立位置，金光取所有脉冲的最大值而不是叠加（避免刺眼）；动画用自有时钟，切到后台再回来不会瞬间跳完。

### 5.3 电子身份牌

`web/phone/phone.js` 在 750×1180 的 Canvas 上绘制：校徽、校名、标题、昵称、染金后的手写签名、单位 / 类型 / 分组 / 路线、有效期、编号、二维码、页脚。签名会先裁掉四周空白再等比缩放，没有签名时用昵称占位。绘制逻辑集中在 `paint()` 与 `paintRest()`，模板到位后改这两处即可。

二维码内容是 `/card/{编号}`。扫开是一个极简核验页，显示昵称、单位、来访类型、分组、参观路线、签到时间，**不显示签名原图**；记录被删除或清空后显示「通行证已失效」。

### 5.4 去重与防刷（大白话）

没有登录、没有账号，靠的是**手机浏览器里存的一个随机串**（`localStorage` 的 `client`），用来认「是不是同一台设备」：

- 同一台手机 **5 秒内**再按一次提交 → 当成手滑，直接返回上次结果，**不新增、不广播**。
- 过了 5 秒、**称呼没变**再提交 → 当成「这个人改了下签名」，更新原来那条记录，大屏**只泛一次金光，人数不变**。
- 过了 5 秒、**换了个称呼** → 当成另一个人（现场共用一部手机的情况），按新签到处理，人数 +1。

所以本地测试「第一次能签、后面改了再提交没反应」不是 bug，是这个规则在起作用。想看人数涨，换个称呼，或换浏览器 / 清一下站点数据。

另外后端还有两道保护：同一 IP 每 60 秒最多提交 12 次；单张签名图解码后上限约 1.2 MB，昵称最长 12 字。

### 5.5 数据与隐私

- 存了什么：昵称、单位、类型、分组、路线、签名 PNG、设备随机串、IP、时间戳。
- 存在哪：服务器上 `server/data/checkin.db`（SQLite，WAL 模式）+ `server/data/sig/*.png`。**没有上传到任何第三方服务**。
- 怎么管：管理接口可删除单条、一键清空、导出 CSV 备份，都需要管理口令。
- 手机端页脚写明「仅用于本次参观签到，记录含昵称与签名，可随时申请删除」。**保留期限话术与访客自助删除入口尚未定稿**，等甲方确认。

### 5.6 断线、重连、常亮

大屏连上后先拉一次 `/api/state` 全量补齐人数与沙粒，再保持 WebSocket；20 秒心跳、50 秒没消息主动重连，断线时右下角出现角标但**不清空已显示的签到墙**，重连后自动补齐。前端每 60 秒申请一次屏幕常亮（Wake Lock），但见 7.4 的限制。

## 六、接口与配置

### 6.1 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `CHECKIN_PORT` | `8000` | 监听端口 |
| `CHECKIN_DATA` | `server/data` | 数据目录（库、签名图、管理口令） |
| `CHECKIN_ADMIN` | 自动生成 | 管理口令；不设则首次启动写入 `<数据目录>/admin_token.txt` |
| `CHECKIN_PUBLIC_URL` | 按请求 Host 推断 | 对外访问地址，写进二维码，正式部署时**务必设置** |

### 6.2 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 跳转到大屏页 |
| GET | `/api/health` | 健康检查，返回人数与连接数 |
| GET | `/api/state?since=毫秒&limit=500` | 拉全量或增量签到记录 |
| POST | `/api/signin` | 提交签到：`{name, unit?, type?, group?, route?, sig?, client?}` |
| GET | `/api/config` | 返回 `{phoneUrl, serverTime}`，大屏据此画二维码 |
| DELETE | `/api/signin/{id}` | 删除单条（需 `X-Admin-Token`） |
| POST | `/api/admin/clear` | 一键清空（需 `X-Admin-Token`） |
| GET | `/api/admin/export` | 导出 CSV（需 `X-Admin-Token`，也支持 `?token=`） |
| GET | `/card/{id}` | 身份牌二维码核验页 |
| GET | `/media/sig/{文件}` | 签名图片 |
| WS | `/ws?role=screen` | 实时订阅 |

### 6.3 WebSocket 事件

服务端 → 大屏：`hello`（连上时的全量状态）、`presence`（在线连接数变化）、`signin`（新增签到）、`update`（改签名，只泛金光）、`remove`（删除一条）、`clear`（清空）、`tick`（20 秒心跳，带人数与连接数）、`pong`（回应客户端 ping）。

大屏处理 `hello / signin / update / remove / clear`；`presence` 与 `tick` 大屏不解析内容，只用来确认这条连接还活着（50 秒没收到任何消息就主动重连）。人数一律以各事件里带的 `count` 为准。

### 6.4 管理口令

首次启动自动生成在 `server/data/admin_token.txt`，调用管理接口时放在请求头：

```bash
curl -H "X-Admin-Token: $(cat server/data/admin_token.txt)" \
     http://127.0.0.1:8000/api/admin/export -o signins.csv
```

也可以用 `CHECKIN_ADMIN` 直接指定。导出接口是 **GET** 不是 POST。

### 6.5 调试参数与快捷键

**大屏 URL 参数**

| 参数 | 作用 |
|---|---|
| `?live=0` | 不连后端，纯本地演示（`file://` 打开时自动如此） |
| `?count=128` | 指定初始人数（仅 `live=0` 生效） |
| `?qr=链接` | 覆盖二维码指向的地址 |
| `?demo=1` | 自动循环模拟签到 |
| `?debug=1` | 按 `O` 半透明叠原型，按 `D` 高亮差异 |
| `?fxsim=毫秒&n=人数` | 模拟签到并直接推演到指定时刻，用于截图检查关键帧 |

**大屏快捷键**：`S` / 空格 = 模拟 1 人，`M` = 模拟 3 人同时签到，`O` = 叠原型，`D` = 差值对比。

**手机端**：`/phone/?demo=1` 会自动填一组样例数据并提交，方便快速预览身份牌。

## 七、部署到正式环境（尚未执行）

> 以下都是**写好的现成配置，还没在目标机器上验证过**。正式部署前请先确认：服务器系统与权限、公网 IP 或域名、防火墙能否放行端口、演示机系统版本与浏览器、是否能设置开机自启。

### 7.1 前提

- 大陆服务器未备案时，只能用非标端口（如 8000）以 IP 直接访问；页面不调用摄像头，HTTP 即可。
- 反向代理放同机时，要允许 WebSocket 升级并放宽读超时，否则长连接会被切断。
- **必须单 worker 运行**，WebSocket 连接表在进程内存里。
- 部署后设 `CHECKIN_PUBLIC_URL`，让二维码指向手机能访问的公网地址。

### 7.2 Linux 开机自启（systemd）

新建 `/etc/systemd/system/checkin.service`：

```ini
[Unit]
Description=签到墙服务
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/check_in
Environment=CHECKIN_PORT=8000
Environment=CHECKIN_PUBLIC_URL=http://<公网IP>:8000
ExecStart=/srv/check_in/.venv/bin/python server/app.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now checkin     # 开机自启并立即启动
sudo systemctl status checkin           # 看是否在跑
journalctl -u checkin -f                # 看日志（启动时会打印管理口令）
```

Windows 上用「任务计划程序」建一个「计算机启动时」触发的任务，程序填 `python.exe`，参数填 `server\app.py`，起始位置填项目目录即可。

### 7.3 大屏开机自动全屏打开浏览器

把下面的命令做成快捷方式，放进启动文件夹（`Win + R` 输入 `shell:startup`）：

```bat
msedge.exe --kiosk --no-first-run --disable-features=TranslateUI "http://<公网IP>:8000/screen/" --edge-kiosk-type=fullscreen
```

`--kiosk` 会全屏、隐藏地址栏和工具栏，再配合 Windows 的「分配访问」还能锁成专用机。这一步需要能操作那台机器，通常归学校信息中心管。

### 7.4 大屏不睡屏

前端已经申请了浏览器的屏幕常亮，但**只在 HTTPS 或本机访问时生效**，用 `http://IP:端口` 访问时浏览器会拒绝。现场要靠系统设置：

1. Windows 设置 → 系统 → 电源：**屏幕和睡眠都设成「从不」**。
2. 关闭屏幕保护程序。
3. 演示前手动唤醒一次，确认整场不会熄屏。

### 7.5 已知现场风险

- **演示机系统**：另有项目组到现场才发现是 Win7 且不能联网，老版浏览器可能不支持本项目用到的部分新 CSS / JS 特性。若机器实在太旧，可把服务跑在另一台机器上，大屏只负责开网页，但仍需浏览器验证。
- **网络链路**：大屏侧要能稳定访问公网；如果靠无线/天线链路，现场先测一次延迟和断线重连表现。
- **公网暴露**：签到页公开，管理接口务必保持口令保护，不要关掉限流。

## 九、交接 FAQ（大白话）

**Q：为什么我第二次提交没反应？**
A：同一台手机 5 秒内重复按算手滑；过了 5 秒、名字没变，算这个人改了下签名，大屏只泛一次金光，人数不涨。换称呼或换个浏览器就能看到人数涨。

**Q：人数是每天清零吗？**
A：不是，目前是累计的。需求原文写了「今日到访 / 已签到 / 当前在线」，但口径没定，已确认先不改，这项记在待办里。

**Q：数据存在哪，会不会外传？**
A：只存在服务器的 `server/data/` 里（一个数据库文件 + 签名图片），没有传给任何第三方。管理员口令可以导出 CSV、删单条或一键清空。

**Q：没有服务器能给老师演示吗？**
A：大屏能。双击 `web/screen/index.html`，按 `S` / `M` 就能看签到特效，不用装任何东西。想看身份牌，需要按第四节起一下服务，然后访问 `/phone/?demo=1`（会自动填样例数据并生成通行证）。「手机扫码 → 大屏实时联动」同样必须起服务。

**Q：为什么不做导览、定位、后台管理？**
A：导览归其他项目组，空间定位已被甲方砍掉，后台管理本次不在范围内。

**Q：为什么身份牌长这样？**
A：按需求描述做了一版，校徽是从原型图裁的占位图。孙博说模板之后再给，模板到位改 `web/phone/phone.js` 里的绘制函数即可。

**Q：Win7 能跑吗？**
A：这是最大不确定项。服务可以跑在别的机器上，但大屏浏览器太旧可能显示不全，需要现场用真机验证一次。

**Q：接下来该从哪一步开始？**
A：等甲方最终原型和身份牌模板 → 确认服务器/网络/演示机 → 按 2.3 的清单补 A3 数字、隐私入口、模板视觉 → 真机验证 → 按第七节部署。
