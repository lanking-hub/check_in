# 部署手册（阿里云轻量 · 11.9 展示版）

> 状态：就绪，等服务器到位。按本文操作，服务器到手后约 30 分钟可上线。
> 功能与样式已冻结，本文只覆盖部署与现场运维。

## 0. 已定决策（不再讨论）

| 项 | 决策 | 原因 |
|---|---|---|
| 访问方式 | `http://<公网IP>:8000`，IP+端口直连 | 域名 ICP 备案来不及；应用不调用摄像头，HTTP 够用 |
| 反向代理 | 不加 nginx | uvicorn 单进程同时托管静态页、API、WebSocket，少一个组件少一个故障点 |
| 进程数 | 单 worker（`python server/app.py`） | WebSocket 连接表在进程内存，多进程会各收一份 |
| 服务器 | 阿里云轻量 4核8G（3000 元/年，报价已列） | 需求范围 v1 已定 |
| 数据落盘 | `server/data/`（SQLite + 签名图片 + 管理口令） | 备份 = 复制目录 |

代码侧已具备、无需改动的部署能力：`CHECKIN_PORT` / `CHECKIN_PUBLIC_URL` / `CHECKIN_DATA` 三个环境变量、监听 `0.0.0.0`、同 IP 限流（每分钟 12 次，超出 429）、WebSocket 心跳保活、CSV 导出。

## 1. 动手前需要拿到的东西

| # | 事项 | 找谁 |
|---|---|---|
| 1 | 服务器公网 IP、root 密码或 SSH 密钥 | 负责采购的同学 |
| 2 | 任意镜像都行：脚本自动适配 Ubuntu/Debian（apt）与 Alibaba Cloud Linux / CentOS / Anolis（dnf/yum）。系统源里没有 Python 3.11+ 时自动装（Ubuntu 走 deadsnakes，RHEL 系装 python3.12/3.11 包），还不行则用 Miniforge 兜底（清华镜像） | 采购时无特殊要求 |
| 3 | 阿里云控制台放行 TCP 8000 端口（轻量的「防火墙」页签，不是系统内防火墙） | 有控制台权限的人 |
| 4 | 大屏一体机的操作权限（装 Edge、改电源设置、开机自启） | 学校信息中心 |
| 5 | 一体机所在位置能否稳定访问公网（有线优先） | 学校信息中心 |

## 2. 服务器部署（两条路任选其一）

### 路线 A：一键脚本（推荐）

把整个项目目录传到服务器 `/srv/check_in`（方式见下方"代码上服务器"），然后 SSH 登录执行：

```bash
cd /srv/check_in
bash deploy/setup-server.sh
```

脚本做的事：检查/安装 Python 3.11+ → 建虚拟环境装依赖（走阿里云 PyPI 镜像）→ 创建 `checkin` 运行用户 → 写入 systemd 服务（开机自启、崩溃 3 秒拉起）→ 启动并做本机健康检查。

**故意不传 `PUBLIC_URL`**：应用会按访问请求的地址自动推断二维码指向（`server/app.py` 的 `/api/config`），所以换服务器、换 IP、换端口都**零配置**——这是镜像化部署的前提。只有当访问路径经过会改写 Host 的代理时才需要显式传 `PUBLIC_URL=http://...` 写死。

### 路线 B：手动逐步（脚本失败时兜底）

```bash
# 1. 确认 Python 版本 ≥ 3.11（Ubuntu 24.04 自带 3.12）
python3 --version

# 2. 装依赖
cd /srv/check_in
python3 -m venv .venv
.venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ -r server/requirements.txt

# 3. 先手动跑一次看有没有报错
CHECKIN_PUBLIC_URL=http://<公网IP>:8000 .venv/bin/python server/app.py
# 看到「签到墙服务已启动」和打印的管理口令即成功，Ctrl+C 退出

# 4. 转入 systemd（单元文件模板见 README「服务开机自启」一节，原样粘贴即可）
```

### 镜像化：换服务器零配置（推荐做法）

在自有服务器上部署验证通过后，把它打成**自定义镜像**，免费服务器到手时直接用镜像创建实例，服务随开机自启，唯一人工步骤是放行 8000 端口。

1. **打镜像前清理**：用管理口令清空签到数据（镜像里不该带测试数据）。管理口令文件会随镜像带过去，演示场景可接受；在意就删掉 `server/data/admin_token.txt`，下次启动自动重新生成。
2. **创建自定义镜像**（控制台操作）：
   - 轻量应用服务器：服务器详情页 → 「创建自定义镜像」
   - ECS：实例列表 → 对应实例 → 镜像/快照 → 「创建自定义镜像」
3. **免费服务器到手后**：
   - 同一地域：创建实例/轻量时镜像类型选「自定义镜像」直接选它 → 开机即服务就绪
   - 不同地域：先把镜像「复制」到目标地域（免费，通常几分钟到半小时），再创建
   - 从轻量换到 ECS（或反向）：走「共享镜像」，要求两边同为 x86 架构，且目标盘容量 ≥ 镜像盘
4. **起来之后验证两项**：`curl http://127.0.0.1:8000/api/health`，以及大屏页二维码指向的地址是否就是新服务器的地址（因为没写死 `CHECKIN_PUBLIC_URL`，理论上自动正确，仍要看一眼）。

边界说明：自定义镜像只在阿里云体系内通用。如果免费服务器不是阿里云的（腾讯云/实体机等），镜像带不过去，到时候再评估是否改用 Docker 方案——对本项目而言 Docker 不是必需品。

### 代码上服务器（GitHub 国内访问慢时的备选）

- 首选：服务器上直接 `git clone https://github.com/lanking-hub/check_in`（轻量服务器出国网一般可达，慢就多等或重试）。
- 备选（不走 GitHub）：本地打包再传，稳定且快：
  ```bash
  # 本地（Git Bash）
  git bundle create check_in.bundle --branches=shx
  scp check_in.bundle root@<服务器IP>:/tmp/
  # 服务器
  git clone /tmp/check_in.bundle -b shx /srv/check_in
  ```

### 部署验证（三步，缺一不可）

1. 服务器本机：`curl http://127.0.0.1:8000/api/health` → 返回 `{"ok":true,...}`
2. **你自己电脑/手机（走流量，不连校园网）**：浏览器开 `http://<公网IP>:8000/api/health` → 能打开说明安全组放行成功。打不开 99% 是控制台防火墙没放行 8000。
3. 手机开 `http://<公网IP>:8000/screen/?demo=1` 看 30 秒：模拟签到自动滚动、无报错，然后进 `/phone/` 真提交一条，确认大屏上出现。测完用管理口令清空。

最后核对大屏页上的**二维码内容**是否等于 `http://<公网IP>:8000/phone/`（由 `CHECKIN_PUBLIC_URL` 决定，这是最容易被写错的配置）。

## 3. 大屏一体机设置（需要信息中心配合）

1. Edge/Chrome 打开 `http://<公网IP>:8000/screen/`，用 kiosk 快捷方式放进启动文件夹（`Win+R` → `shell:startup`）：
   ```bat
   msedge.exe --kiosk --no-first-run --disable-features=TranslateUI "http://<公网IP>:8000/screen/" --edge-kiosk-type=fullscreen
   ```
2. 电源：设置 → 系统 → 电源，**屏幕和睡眠都设「从不」**；关屏保。页面虽申请了屏幕常亮，但 HTTP 下浏览器会拒绝 Wake Lock，必须靠系统设置兜底。
3. 演示前一天实地彩排一次：断电重启 → 自动开机 → 自动全屏打开页面 → 数据正常恢复。

## 4. 演示日流程（D-day checklist）

**开场前 30 分钟**
- [ ] `systemctl status checkin` 确认服务在跑（或 `curl http://127.0.0.1:8000/api/health`）
- [ ] 管理口令清空历史数据（`POST /api/admin/clear`，口令在 `server/data/admin_token.txt`）
- [ ] 手机走流量真扫一次全流程：提交 → 大屏出现 → 通行证可保存
- [ ] 确认大屏二维码指向的地址就是当前公网地址
- [ ] 大屏不熄屏、不锁屏

**兜底预案（万一公网炸了）**
- 笔记本跑同一套服务（本地 `.venv` 现成的），笔记本开 WiFi 热点，一体机和几台测试手机连热点，二维码换成 `http://<笔记本IP>:8000/phone/`（`?qr=` 参数可临时覆盖）。演示效果不变，只是覆盖人数少。

## 5. 故障排查表

| 症状 | 大概率原因 | 处理 |
|---|---|---|
| 外网访问不了，本机 curl 正常 | 阿里云控制台防火墙没放行 8000 | 控制台 → 防火墙 → 添加规则 TCP 8000 |
| 服务没起来 | 依赖没装全 / Python 版本 | `journalctl -u checkin -n 50` 看报错 |
| 手动跑正常、systemctl 起不来 | SELinux（CentOS 系常见，Alibaba Cloud Linux 默认关闭） | `getenforce` 确认，`setenforce 0` 临时放开验证 |
| 手机提交 429 | 同 IP 限流（每分钟 12 次） | 正常防护，稍等即可；彩排时别用同一路由器狂刷 |
| 大屏不实时更新 | WebSocket 被掐（只在不加代理直连时基本不会发生） | 刷新页面即可重连；`/api/state` 全量兜底 |
| 忘了管理口令 | — | `cat /srv/check_in/server/data/admin_token.txt` |
| 想彻底重置 | — | 清空接口，或停服务后删 `server/data/` 目录再启动 |

## 6. 安全底线

- SSH 用密钥、禁密码登录（买完服务器第一件事）；8000 以外的端口一律不开。
- 管理口令只发给现场负责的同学，不要进群。
- 数据含访客姓名与单位：展示结束后导出 CSV 备份一份，然后清空服务器数据；泄露面最小化。
